# Gifto Khussa build outcomes

- [ ] **Brand shell and responsive foundation** — The site uses the Gifto Khussa crimson, brass gold, cream/ivory and charcoal palette; serif display type and clean sans body type; responsive header with mobile drawer; sticky mobile bottom bar for Home, Shop, Cart and WhatsApp; 44px+ touch targets; no horizontal overflow at 360px, 390px, 414px, 768px, 1024px and 1440px.

- [ ] **Replaceable image system** — Every hero, collection, craft-process, gallery, about, outlet, contact, product and brand image slot is named, documented with recommended size/aspect ratio, easy to replace, and does not depend on random stock imagery. The interim text logo and favicon can be replaced from Store Settings.

- [ ] **Animated public storefront** — Home includes animated hero, featured collections, new arrivals, best sellers, handcrafted process, counters, testimonials, gallery, newsletter and footer. Shop includes search, category/size/color/price/stock filters, sorting, quick add, and responsive filters. Product detail includes gallery, zoom treatment, price/discount, selectors, stock, quantity, cart, WhatsApp order, size guide, delivery note, reviews and related products. Public pages include About, Contact, FAQ, Shipping & Returns, Size Guide, Privacy, Terms, Outlet Locator and 404. All pages have route transitions/reveal states, a top scroll progress indicator, navbar hide/show behavior and reduced-motion support.

- [ ] **Cart, wishlist and WhatsApp ordering** — Cart and wishlist persist in localStorage. Cart supports quantity updates, remove, clear, subtotal and a validated order form for name, phone, address, city and notes. WhatsApp opens a `wa.me` link with the structured order message and configured +923094148870 number; product pages have direct WhatsApp ordering; every order is recorded as pending; delivery charges are never calculated and the exact note “Delivery charges will be confirmed on WhatsApp.” appears on cart and product pages; floating WhatsApp action does not overlap the mobile bar.

- [ ] **Admin workspace** — `/admin` is protected by a demo login and has dashboard metrics, products, categories, multi-image product data, inventory/outlets, order status management, customers/newsletter export, homepage/image settings, reviews moderation and store settings. On phones, tables become cards and the sidebar becomes a drawer. Store settings include logo, WhatsApp, contact, social links, currency, shipping text, policy copy and admin email/password change fields.

- [ ] **Supabase-ready persistence** — `supabase/schema.sql` defines products, categories, product_images, outlets, orders, order_items, customers, reviews, newsletter_subscribers, site_settings and admins with indexes/constraints; `supabase/seed.sql` includes 12–15 products and categories. `.env.example` documents Supabase values and the app remains usable with local seeded data before keys are provided.

- [ ] **Quality and delivery** — Include semantic HTML, route metadata, Open Graph/Twitter tags, sitemap/robots, `manus-routes.json`, loading/empty/error states, validation, security-oriented server seam, README, Dockerfile and deploy notes. Run the production build, inspect the route manifest, verify the HTTP server on port 3000, and check representative responsive screenshots before checkpointing.
